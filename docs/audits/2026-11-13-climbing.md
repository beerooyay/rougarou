# Climbing-system audit — 13 November 2026

Baseline: c875c49. Scope: the live web path, its Unreal counterpart, native
character hierarchy, contacts, input, support/strain/slip rules, pose fitting,
joint constraints, and regression/deployment gates. This is a source and
representative runtime audit, not a proof over every possible climbing move.

## Ownership and the failed contract

| Layer | Implementation | Responsibility / finding |
| --- | --- | --- |
| Input | web/main.js | Raycast hold triangles and store lateral placement. Selection preserves support until movement. Picking was based on flattened sim tips, not the visible shoe/hand. |
| Rules | web/sim.js / ClimbSim.cpp | 60 Hz unrolled-wall torso, force sharing, directional grip, placement quality, pump, friction-only smears, overload slips and reach failure. A latch is simulation arrival, not measured native-skeleton arrival. |
| Surface | web/gym.js, hold-contact.js | Collision field rasterized from rendered hold triangles; upper shoulder for shoes, knuckle target and finger clearance for hands. |
| Pose intent | web/climber.js / ClimberActor.cpp | Stance-dependent hips/chest, high steps, reach twist, hanging limbs. Independent depth/height heuristics cannot by themselves guarantee four native contacts. |
| Native mesh | web/skin.js / HumanRig.cpp | Fixed-length anatomical chains, joint limits, sole/knuckle landmarks, finger fit. Native whole-body fitting was only partially represented in the web adapter. |
| Limits / smoothing | web/human-motion.js | Joint envelopes and bounded motion. Applying smoothing after a contact solve changes the actual contact. Repeated wrist fitting can fight the hand-surface objective. |
| Handoffs | main.js, ragdoll.js, world.js | Walk/climb/retry/fall transitions; ragdoll uses the procedural pose, not an articulated force simulation of the native skeleton. |
| Validation | check.mjs, tests/web-rig, Pages workflow | Simulation solvability alone never established native-model contact accuracy. |

The simulated arms have 55 cm of segment length plus an 8 cm reach allowance;
the shipped native skeleton measures approximately 46–47 cm shoulder-to-wrist.
Simulation depth is 10–14 cm while pose intent often puts the pelvis 40–70+ cm
out. These are different representations, not interchangeable measurements.
Do not fix their mismatch by stretching bones, forcing knees outward, or
loosening all joint limits.

## Repairs in this change

- Select the native model's actual sole/knuckle screen position.
- Blend a travelling foot toward the hold surface before arrival, matching the
  hand approach principle. Mirror this target transition in Unreal.
- Fit shared pelvis translation **and rotation** from actual contact errors.
  Opposing foot errors require turning the body; translation alone cannot fix
  them. Prioritize larger misses, bound motion/offsets, retain a 28 cm pelvis
  clearance floor, and stop chasing sub-centimeter residuals.
- Prefer economical overhead arm extension only when contacts are already
  accurate. This is a soft preference; it does not lock elbows straight.
- Refine the bounded animated shoe pose after smoothing, preserving downstream
  local transforms and the same joint motion budget. Hand fitting retains its
  surface objective; a second wrist correction was experimentally regressive
  and was removed.
- Stop re-optimizing an accurate, safely placed chain. Finger curl presets and
  finger-fitting code are unchanged.
- Port finite wall-strip clearance: the old web query extended adjacent panels
  15 cm beyond their physical edge, creating phantom thumb collisions.
- Reset body correction, joint-history, swivel and garment state on retry.
  Only explicit planted contacts drive body fitting; a ragdoll foot is not a
  support merely because its metadata omits `held`.
- Share the real GLB skeleton fixture. Add all-route, both-side contact and
  sampled-digit regression coverage to the deployment gate. Tighten the older
  high-step tolerance from 6 cm to 2 cm.

## Evidence

The initial 45-pose audit found 22 attached contacts farther than 2 cm from
their rendered targets; the worst was 11.3 cm. Several candidate changes were
rejected for worse contact error or stationary wrist jitter.

Final scene-aware measurements are in [the 81-pose trace](2026-11-13-web-climbing.json):

- 0 settled contacts outside 2 cm; worst miss 1.501 cm.
- 0 sampled digit penetrations; minimum sampled clearance 0.633 cm.
- Focused high-step sole errors: 0.298 and 0.604 cm.
- Stationary late joint motion: 0.020 degrees per frame.
- Maximum joint-envelope error: 0.052 degrees; no inward knee crossing in the
  focused high-step sequence.
- Both knee and elbow response tests pass (roughly 22–56 degrees of flexion).
- Browser selection: rendered pelvis displacement below 0.000001 cm when
  selecting each planted limb; a new hold changed it by 0.914 cm on the first
  frame. Visible-limb picking and step/return passed.
- All nine simulation routes remain sendable; all 16 native tests passed.

The [baseline trace](2026-11-13-baseline-contacts.json) used 45 poses (one foot and
one hand per route), so its coverage is smaller than the final 81-pose set.

The test commands are:

```
node web/check.mjs
npm test --prefix tests/web-rig
npm run audit --prefix tests/web-rig
```

Browser `interaction-check.html` additionally exercises picking, selection,
placement and foot return in the actual WebGL application. The native editor
was rebuilt and all 16 Rougarou automation tests passed.

## Remaining boundaries / architecture debt

- The rules remain a 2D torso/contact model. Native contact fitting improves
  visual feasibility but is not fed back as a full 3D force/contact constraint.
  Unusual moves can still expose disagreement between reach admission and
  native anatomy. A unified, deterministic 3D contact contract is the next
  architectural step; do not widen reach limits without testing native reach.
- Digit checks sample joint centerlines, segment midpoints and estimated tips
  against wall/hold surfaces. They do not prove clearance of every skinned
  vertex or continuous swept collision between frames.
- The 81 integration poses cover starts plus one reachable move and return per
  limb on every route. They are not every click location, complete native-rig
  ascents, or a hardware trackpad usability test.
- Procedural mannequin/fall lengths and the imported rig remain separate.
  The mannequin is an intentional fallback/pose generator, not a duplicate
  native player to delete casually. Fall handoffs warrant dedicated rendered
  continuity coverage before further changes there.
- Hold collision fields are front heightfields; concave pockets and rotated
  foothold support direction have limits compared with full mesh contact.
- This audit does not delete experimental labs, artist source assets or older
  player assets. Their existence is not evidence that the live path uses them.
